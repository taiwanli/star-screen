> 审查日期：2026-09-27 ｜ 审查范围：pub workspace（8 包 + 3 端）、docs 01–12、tools、CI
> 方法：基于仓库实际存在的文件逐模块阅读（domain / plugins / storage / lan / player / ui_kit / 三端壳 / 文档 / 工具脚本），

## 1. 执行摘要

项目整体工程成熟度高于「v0.1 开发中」的直觉印象：文档体系完整（12 篇，与设计/实现强互引）、
领域层纯净（架构守护 CI 强制）、测试资产充足（纯 Dart 包约 142 个 test 单元）、
合规基线（不内置源、不执行 jar、needsParse 默认拦截）在代码层有真实实现。主要风险集中在四类：

1. **播放主链路有一处真实逻辑缺陷**：`PlaybackSession` 的 5 秒节流按「绝对位置差」判断，
   多集顺序播放时会出现「后续集不写库」的边界行为（低概率但影响续播正确性）。
2. **局域网互连功能处于「半接线」状态**：推片载荷是写死的演示地址、接收端 `onPlayPush` 为空实现、
   手机/TV 端无「推片接收」UI，且 `LanServer` 的 `/backup` 无请求体大小限制（安全项）。
3. **订阅 ETag/304 管线与文档宣称不符**：`subscriptions` 表（含 etag/raw 列）无任何代码读写，
   ETag 闭环实际不存在；304 在 CMS 适配器中被直接当作异常抛出。
4. **文档与代码存在多处不一致**：文档自报测试数（83/129/78）与仓库实际不符、
   EPG/数字键换台的端覆盖描述与代码不符、CHANGELOG 存在被截断的条目、根目录有 15 个垃圾探针文件未清理。

代码风格总体克制、注释解释「为什么」且文档互引到位，技术债务可控；以下问题按优先级给出可操作步骤。

## 2. 问题清单

### A. 代码质量

**A1. `PlaybackSession._save` 的 5 秒节流按绝对位置差判断，跨集/回退场景漏写库（中）**
- 证据：[packages/domain/lib/src/playback/playback_session.dart:154-160](packages/domain/lib/src/playback/playback_session.dart)
  `_onEvent` 中 `if (positionSec - _savedAtSec >= 5) _save(...)`；`start()` 把 `_savedAtSec = -1`、
  `resumeAt` 可能很大（续播从 80% 起）。后果：
  - 续播后位置从 7200s → 7205s 立即触发一次落盘（可接受），但 seek 回 0s 后，
    `positionSec - _savedAtSec` 为负，直到位置再次追平旧值才会写库 —— 进度记录会长时间停留在旧值。
  - 换集（`switchTo`）时 `start()` 重置 `_savedAtSec = -1`，此路径正确；问题仅在「同一集内向前 seek 很远」时出现。
- 影响：低概率下「继续观看」显示过期进度；不崩溃，属数据新鲜度缺陷。
- 建议：节流改为「距上次落盘 *经过的时间* ≥5s」（记录 `_lastSaveAt` 时间戳），或保留位置差但改用
  `abs(positionSec - _lastSeenSec) >= 5` 语义，并补一个「向前大 seek」的单测。

**A2. `LanServer` 的 `/backup` POST 无请求体上限（高，安全）**
- 证据：[packages/lan/lib/src/lan_server.dart:71-79](packages/lan/lib/src/lan_server.dart)
  构造函数声明了 `maxBodyBytes = 8 * 1024 * 1024`（注释「防超大备份打爆内存」），
  但 `_handle` 中 `/play` 与 `/backup` 的 `utf8.decodeStream(req)` 都没有按 `maxBodyBytes` 截断。
  该字段定义了却没被使用。
- 影响：局域网内任意设备可向本机 47891 端口灌入无上限数据（若 `authToken` 未配置则完全无防护）。
- 建议：读取时限制累计字节数，超限返回 413；把「是否已按 8MB 截断」补进 docs/10 的 D 组走查。

**A3. 根目录 15 个探针垃圾文件 + `probe_report.md` 含真实站点名（中）**
- 证据：根目录存在 `100`、`115`、`140`、`15`、`155`、`165`、`180`、`20`、`200`、`24`、`300`、`40`、
  `470`、`55`、`ProbeResult(probeName`（均为 2 字节左右）；[tools/probe_report.md](tools/probe_report.md)
  记录了大量真实第三方站点 URL 与状态（含成人内容站点名）。
- 影响：垃圾文件污染工作区与任何 `git add .`；报告文件发布到 GitHub 会传播来源信息，
  与「内容中立、不内置源」的合规叙事冲突（实测记录属开发资产，不宜随仓库公开）。
- 建议：删除 15 个垃圾文件；`probe_report.md` 与 `source_samples.json` 加进 `.gitignore`
  （当前 `.gitignore` 没有覆盖这两项），或移出版本库；fixtures 目录已是脱敏路线，与之一致。

**A4. `DownloadService` 断点续传对「服务器不支持 Range」的进度显示错误（低）**
- 证据：[packages/storage/lib/src/download_service.dart:74-83](packages/storage/lib/src/download_service.dart)
  `received > 0 && !resumeOk` 时 `received = 0` 但 `current` 已在外层被 `copyWith(receivedBytes: received)`
  写入旧值；随后只有每 256KB 才更新一次 store，首段进度条会回跳/闪烁。
- 影响：纯 UI 层小瑕疵，不影响正确性。

**A5. `FlutterJsRuntime._pump` 用 10ms 周期 Timer 泵事件循环（低，性能）**
- 证据：[apps/desktop/lib/src/flutter_js_runtime.dart:60-72](apps/desktop/lib/src/flutter_js_runtime.dart)
  每次 JS 片段异步求值期间持续 100 次/秒调用 `executePendingJob`。对 drpy `await req(...)` 类
  片段（单次可达 20s）是固定开销；CPU 占用极低但属不必要的忙轮询。
- 建议：flutter_js 若有 `Promise` 完成事件则订阅之；没有的话维持现状并注释说明取舍即可。

- 证据：

  功能演示时用户只会收到一个永远播不通的 example.com。
- 建议：桌面端把 `player_page` 的投屏按钮改为真实 `session._candidate.url`（代码注释里作者已承认

**B2. ETag 订阅管线「建了表、没接线」（中，文档不一致）**
- 证据：
  - [packages/storage/db/schema.sql](packages/storage/db/schema.sql) 的 `subscription` 表含 `etag/raw/fetched_at`；
    `source_def.sub_id` 外键到它；但全仓库 `rg "db.subscriptions"`（非 .g.dart）无命中，
    该表零读写代码。
  - `FeedFetcher.fetchSubscription(etag: ...)` 参数存在（[feed_fetcher.dart:18-22](packages/domain/lib/src/net/feed_fetcher.dart)）
    但没有任何调用方传入 etag；`DriftBackupCodec` 不导出订阅行。
  - 同时 [cms_json_source.dart:48](packages/domain/lib/src/adapters/cms_json_source.dart) 与
    [cms_xml_source.dart:34](packages/domain/lib/src/adapters/cms_xml_source.dart)
    对 304 的处理是 `throw FetchException('缓存协商返回 304，但无缓存可用')` —— 即 CMS 适配器

  只在 `FeedFetcher` 单元层面成立，端到端不存在。
- 建议：要么实现订阅 upsert 落库（`subscriptions.id` 回填 `source_def.sub_id`）+ 周期刷新带 etag，
  要么把 docs/05 §5 的 ETag 段落与 README 里「M0 …（ETag/UA）」标注降级为「接口就绪、未接线」。

**B3. `QualityTrack`/清晰度切换是空壳（低）**

### D. 性能

**D1. 详情/列表 HTML 重复解析（中）**
- 证据：[packages/plugins/lib/src/drpy_template_source.dart]
  - `_parseList` 对每个列表元素调用 `_fragPdfh`，而 `_fragPdfh` 每次 `html_parser.parse(el.outerHtml)`
    （把元素 outerHTML 重新整段解析为 DOM）—— 一个 50 项分类页 = 50×N 次完整 DOM 解析。
  - `home()` 先 `PdfhEngine.pdfa(html, ...)`（解析一次全文），随后 `_fragPdfh` 又逐元素解析；
    `_detailFromTemplate` 中 `pick()` 用已解析的 `doc`，但 tabs/lists 仍走 `PdfhEngine.pdfa(html, ...)`
    再全文解析一次。
- 影响：模板源浏览/搜索在中低端盒子（TV 目标场景）上 CPU 明显；纯 Dart 包性能单测缺失无法量化。
- 建议：`PdfhEngine` 增加「对已解析 Document 求值」的重载（当前 pdfh 已支持 root 参数，
  把 pdfa 也改为 `pdfa(Document, rule)` + 顶层便利方法 `pdfa(html, rule)`），
  列表解析改为一次 `parser.parse` 后在内存 DOM 上求值；补一个 50 元素列表的基准测试。

**D2. `CmsJsonSource._cache` 淘汰策略是「按插入序取前 1/4」（低）**
- 证据：[packages/domain/lib/src/util/ttl_cache.dart:24-32](packages/domain/lib/src/util/ttl_cache.dart)
  `set` 超限后 `_map.keys.toList().take(length ~/ 4)` 移除 —— Dart 的 `Map` 是插入序，
  该策略会删掉**最旧插入**的键，但若热点请求反复命中已存在的键（不触发 set），它们永远不会被重新排序，
  行为接近 LRU 但不严格；更隐蔽的是 TTL 过期键不会被惰性清理，只在 `get` 命中时删除。
- 影响：内存上界确定（128 条 JSON），风险低；但「最旧淘汰」在「先取后 put」模式下可能淘汰热点键。
- 建议：换 `LinkedHashMap` 的 move-to-end 语义或直接用现成的 LRU 实现；保持 maxEntries 不变。

**D3. `TvFocusMemory._last` 是静态 Map，无界增长（低）**
- 证据：[apps/tv/lib/src/widgets/tv_focus_engine.dart:14-26](apps/tv/lib/src/widgets/tv_focus_engine.dart)
  每访问一个 `pageKey` 增一条；长会话切几十页后累积。单条极小，但属可避免的静态泄漏。
- 建议：上限 64 条 + FIFO 淘汰，或随 `TvFocusScopeState` 生命周期挂到实例上。

### E. 安全

**E1. `LanServer` 无认证时 `/backup` 可被任意设备拉走全部用户数据（高）**
- 证据：[lan_server.dart:29-31](packages/lan/lib/src/lan_server.dart) `authToken` 为 null 时
  `/_authed 恒 true`；`GET /backup` 返回 `backup.exportAll()` 全量 JSON（源定义 + 播放记录 + 收藏 + 设置）。
  默认 `LanBridge` 构造未传 authToken（三端 app_services 均如此），即出厂状态是**同网段无防护**。
- 影响：同路由器下的任何设备可读取用户的源订阅 URL（可能含用户私有内容源地址）与观看历史。
- 建议：默认生成随机 token 并落 KV，UI 展示「配对口令」；docs/10 D 组增加「无口令不得互信」红线。

**E2. `IoHttpFetch.trustSelfSigned` 无调用方（低，提示项）**
- 证据：[http_fetch.dart:97](packages/domain/lib/src/net/http_fetch.dart) 提供了开关，
  但全仓库无 `trustSelfSigned: true` 的构造调用 —— 即 docs/11 实测中「卧龙/如意等需要信任自签证书」
  的源在当前产品里仍然连不上，UI 文案却承诺「可在源设置中信任该证书」（`FetchException` 文案，
  http_fetch.dart:146）。
- 影响：功能承诺与能力不一致；用户看到提示却找不到设置入口。
- 建议：要么把开关接到「源管理 → 高级」，要么临时把异常文案改为「暂不支持自签证书源」。

**E3. 备份 JSON 无「可加密」能力（低）**
- 证据：[star_storage.dart](packages/storage/lib/star_storage.dart) 注释写
  「全量导出为可加密 JSON 文本」，但 `DriftBackupCodec.exportAll` 是明文 JSON，无加密实现。
- 建议：注释改为「明文 JSON（加密 v0.9+）」，或按 docs/03 排期实现。

## 3. 优化方案（按实施优先级排序）

| # | 优先级 | 针对 | 改进步骤 | 预估工作量 |
