## 4. 引擎打磨记录（按实测反馈逐项修复）

| # | 反馈问题（首轮现象） | 修复 | 回归验证 |
|---|---|---|---|
| F1 | `c00·wh0` 多仓识别为乱码 | `ConfigCleaner.decodeBytes`：UTF-16LE/BE BOM 智能解码（响应体与本地文件均走此路径） | ✅ 识别 45 子仓 |
| F2 | `qist·XYQ` 合法配置解析失败 | 三级 JSON 容错新增「字符串内未转义控制字符转义」修复层 | ✅ 49 站 |
| F3 | `gao·0707`/`c00·wh0515` 的 `{"urls":[…]}` 多仓变体不识别 | `TvBoxConfigParser` 新增 urls 变体支持 | ✅ 分类正确 |
| F4 | `海外看`/`卧龙` 等自签证书 TLS 失败 | `IoHttpFetch(trustSelfSigned:)` 选项 + HandshakeException 专用提示（含处置建议） | ✅ 森林恢复；卧龙确认为真死 |
| F5 | 无效源提示缺少上下文 | 解析失败消息带来源 URL 与处置建议（失效/网页入口） | ✅ 全部失败项可读 |
| F6 | 个别「慢滴漏」服务器挂死读取 | 响应体读取纳入超时控制；探测器加每条 60s 硬看门狗 | ✅ 复测必然收敛 |
| F7 | `ww` 仓库 404 | 样本分支修正（main→master，经 API 核实） | ✅ 5 个配置恢复 |

**修复后新增的明确提示项**（引擎对无效/特殊源的提示能力验证）：
- 顶层为 CMS 响应结构 → 「该地址应作为 CMS 接口源添加，而不是 TVBox 订阅」
- 网盘聚合形状（Alist/QiQi/YSDQ…）→ 「未知结构」+ P2 路线说明
- 需原生蜘蛛 jar → 「依赖 DexClassLoader，星映不执行——可改用 JS 源替代」
- HTML 入口页 → 「页面（入口型接口）」+ 页面内 .json 直链提取建议
- TLS 失败 → 「自签/过期证书」（docs/13 E2：v0.1 暂无设置入口，文案已对齐代码；v0.2 提供后启用信任开关）

## 5. 引擎兼容性结论（v0.1）

- **配置解析覆盖率**：63 主样本中可获取的 50 个 → 结构解析成功率 **100%**（含 UTF-16/注释/控制字符/尾逗号容错）；解析失败的 3 个均为深度损坏，提示明确。
- **站点级支持**：CMS JSON/XML、XPath 规则、drpy JS（M3 沙箱后可用）、Alist 已注册；jar 蜘蛛源按矩阵明确标「不支持+原因」。
- **端到端验证**：28 条内嵌 CMS 线路完成「列表→详情→play_url」全链路验证。
- **后续**：jk9/gtb 深度损坏不做无限修复（保持明确提示）；YSDQ 网盘聚合形状随 P2 Alist 挂载支持；drpy JS 运行时 M3 上线后 `gao·js` 298 源将转为可用。
