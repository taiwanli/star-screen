# 星映源写规范（StarRule v1）· 三端统一源规则

> 版本：StarRule **1.0** ｜ 日期：2026-09-28
> 目标：手机 / 桌面 / TV **三端共用同一套源规则**，写一次处处可跑。
> 上游参考：[04-订阅源规范深度调研](./04-订阅源规范深度调研.md)、[05-源管理引擎开发报告](./05-源管理引擎开发报告.md)
> 配套：[18-源管理交互改造](./18-源管理交互改造.md)

## 1. 为什么要做 StarRule

### 1.1 生态现状的痛

| 问题 | 现状 | 后果 |
|---|---|---|
| 规则碎片化 | TVBox `type 0/1/3`、`csp_*` jar、drpy `var rule`、海阔中文键、hipy t4 | 一个站要在多种格式间翻译，作者负担重 |
| 三端能力不齐 | jar 蜘蛛依赖 Android `DexClassLoader`；桌面 `UnsupportedJarHost` | 手机/TV 能看的源，桌面整类不可用 |
| 契约不统一 | CMS 走 `?ac=list`，蜘蛛走 Java 方法，drpy 走 JS 函数 | 上游要为每种形态写分支 |
| 规则不可校验 | 各家字段缺省、语义靠猜 | 写错了只能「导入后看哪里挂」 |

### 1.2 StarRule 的定位

**一套声明式 JSON 规则**，描述「怎么从站点拿到片单 / 详情 / 播放地址」：

1. **纯数据、可校验**——JSON Schema 可机器检查，不依赖任何运行时方言。
2. **三端同一解释器**——Dart 原生求值（选择器子集 + 模板 + 正则），**不跑 jar、不跑 JS 也能覆盖 80% 站点**。
3. **可转译**——TVBox XPath 规则、drpy 纯模板源、CMS 站点声明，都能自动/半自动转成 StarRule。
4. **可扩展**——复杂逻辑走可选 `script` 块（QuickJS，三端同构），但**规范默认不要求脚本**。

### 1.3 与现有形态的关系

```
                    ┌─────────────────────────┐
   TVBox 单仓/多仓 ──►  导入解析器 TvBoxConfigParser │
                    └───────────┬─────────────┘
                                │ 归一
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   type=0/1 CMS           type=3 + csp_XPath*      type=3 + *.js
   → CmsJson/Xml          → 转译为 StarRule         → DrpyTemplateSource
   （已有适配器）           （新 StarRuleSource）      （已有，纯模板可跑）
                                │
                                ▼
                    ┌─────────────────────────┐
                    │  SourceKind.starRule     │  ★ 三端统一
                    │  StarRuleSource          │
                    └─────────────────────────┘
                                │
        csp_* 非规则 jar ──► spiderJar（仅 Android/TV 桥）
                             桌面显示「该源需 jar，建议用 StarRule 重写」
```

**原则**：能用 StarRule 表达的，优先 StarRule；CMS 保持直连（性能最好）；jar 蜘蛛保留兼容但不再扩展。

## 2. 文件形态

- 扩展名：`.star.json` 或任意 `.json`（含 `"starrule": 1` 字段即可识别）
- 编码：UTF-8（无 BOM 优先；容错剥 BOM）
- 单文件 = **一个站点**；也支持 **规则包**（`"sites": [...]` 数组，见 §9）
- 相对 URL 相对**规则文件自身地址**解析（与 TVBox 配置一致）

```json
{
  "starrule": 1,
  "meta": { "id": "demo.movies", "name": "示例影视", "version": "1.0.0" },
  "site": { "host": "https://example.com" },
  "home": { },
  "category": { },
  "detail": { },
  "search": { },
  "play": { }
}
```

## 4. 选择器与模板语言（三端共用核心）

StarRule 的取值规则统一为 **「选择器链 + 取值后缀」**，与现有 `PdfhEngine`（drpy pdfh 子集）同语法，**零新方言**。

### 4.1 选择器链

```
段1&&段2&&…&&段N&&取值
```

- `&&` 分层下钻；每段是 CSS 选择器子集：`tag` / `.cls` / `#id` / `tag.cls` / `div.item a`
- 支持 `:eq(n)` 取第 n 个命中（0 起）；`:eq(-1)` 最后一个
- 列表规则：整个链决定「哪些节点是条目」；字段规则在**条目节点内**再下钻

**示例**

| 规则 | 含义 |
|---|---|
| `body&&.module-item` | 列表：body 下每个 `.module-item` |
| `.title&&Text` | 字段：条目内 `.title` 的文本 |
| `a&&href` | 字段：条目内 `a` 的 href |
| `img&&data-src` | 字段：`img` 的 data-src |
| `.list:eq(0)&&a&&href` | 第 0 个 `.list` 下的 a 的 href |

### 4.2 取值后缀

| 后缀 | 含义 |
|---|---|
| `Text` / `text` | 元素文本（trim） |
| `html` | 内部 HTML |
| 其他标识符 | 同名属性（`href` `src` `data-src` `title` …） |

### 4.3 JSON / XML 模式（`sourceType: "json"` 或字段前缀）

| 前缀 | 含义 | 示例 |
|---|---|---|
| `json:path.to.field` | JSONPath 简化（点号 + 数字下标） | `json:data.list` / `json:data>list>0>name` |
| `xml:/path/to/node` | XPath 简化子集 | `xml://item/title` |
| `cms:vod_name` | 苹果 CMS 字段直取 | `cms:vod_name` |

> 说明：`json:` 的 `>` 与 `.` 等价，兼容生态里两种写法。列表规则用 `json:data.list` 表示「每个数组元素是一个条目」。

### 4.4 模板占位符

| 占位符 | 出现位置 | 含义 |
|---|---|---|
| `{host}` | 任意 URL | `site.host` |
| `{cateId}` | category.url | 当前分类 id |
| `{cateName}` | category.url | 当前分类名 |
| `{catePg}` | category.url / search.url | 页码，从 1 起 |
| `{vid}` | detail.url / play.url | 作品 id |
| `{wd}` | search.url | 搜索词（**已 URL 编码**） |
| `{playUrl}` | play.url | 详情页取出的原始播放链 |
| `{lineId}` | play.url | 当前线路 id |

相对 URL 一律相对 `site.host`（或规则文件 URL）补全。

### 4.5 后处理（字段级）

字段值可声明后处理，放在字段对象形态：

```json
"title": {
  "sel": ".title&&Text",
  "regex": "^(.+?)\\s*更新",
  "replace": "$1",
  "default": "未知",
  "trim": true
}
```

| 键 | 说明 |
|---|---|
| `sel` | 选择器链（同字符串形态） |
| `regex` | 取第一个匹配；无组时整段，有组取 group1 |
| `replace` | `regex` 未用时的整串替换目标；支持 `$1` 反向引用 |
| `default` | 取空时的兜底 |
| `trim` | 是否 trim，缺省 true |
| `absUrl` | true 时对 URL 结果补全绝对地址，缺省自动（href/src 类默认补全） |

字符串形态等价于 `{"sel": "…"}`。

## 5. 块字段详解

### 5.1 home（首页）

```json
"home": {
  "url": "/",
  "recommend": {
    "list": "body&&.module-item",
    "title": ".title&&Text",
    "id": "a&&href",
    "cover": "img&&data-src",
    "badge": ".note&&Text"
  },
  "categories": {
    "mode": "manual",
    "manual": { "电影": "1", "剧集": "2", "综艺": "3" },
    "parse": {
      "list": ".nav&&a",
      "name": "Text",
      "id": "href"
    }
  },
  "filters": {
    "1": [
      { "key": "year", "name": "年份", "options": [
        { "label": "全部", "value": "" },
        { "label": "2026", "value": "2026" }
      ]}
    ]
  }
}
```

| 字段 | 说明 |
|---|---|
| `url` | 首页路径，相对 host |
| `recommend` | 推荐流字段映射（同 category 条目字段） |
| `categories.mode` | `"manual"`（写死）\| `"parse"`（从页面抠）\| `"cms"`（接口 class） |
| `filters` | 筛选器，按分类 id 挂；`options[].value` 会进 category.url 的 `{filter_xxx}` |

**条目字段映射**（recommend / category / search 共用）：

| 键 | 必填 | 说明 |
|---|---|---|
| `list` | ✅ | 列表选择器 |
| `title` | ✅ | 标题 |
| `id` | ✅ | 详情 id 或详情 URL |
| `cover` | | 海报 |
| `badge` | | 角标（更新至 / HD …） |
| `year` / `area` / `type` / `score` | | 可选元数据 |
| `idIsUrl` | | id 是否已是完整 URL（相对 host 补全） |

### 5.2 category（分类片单）

```json
"category": {
  "url": "/type/{cateId}-{catePg}.html",
  "list": "body&&.module-item",
  "title": ".title&&Text",
  "id": "a&&href",
  "cover": "img&&data-src",
  "badge": ".note&&Text",
  "pageCount": {
    "sel": ".page&&Text",
    "regex": "共(\\d+)页"
  },
  "hasMore": "auto"
}
```

| 字段 | 说明 |
|---|---|
| `url` | 列表 URL 模板，必含 `{catePg}` 或靠 `hasMore` |
| `list` + 字段 | 同条目映射 |
| `pageCount` | 总页数提取（可选） |
| `hasMore` | `"auto"`（list 非空即有下一页）\| `"pageCount"` \| `"none"`（单页） |

筛选参数进 URL：`{filter_year}` 这类占位符来自 `home.filters` 的 key。

### 5.3 detail（详情）

```json
"detail": {
  "url": "/detail/{vid}.html",
  "title": "h1&&Text",
  "cover": ".poster&&img&&src",
  "desc": ".intro&&Text",
  "year": ".meta&&.year&&Text",
  "actor": ".meta&&.actor&&Text",
  "director": ".meta&&.director&&Text",
  "area": ".meta&&.area&&Text",
  "type": ".meta&&.type&&Text",
  "remarks": ".remarks&&Text",
  "lines": {
    "list": ".tabs&&span",
    "name": "Text",
    "episodes": {
      "list": ".playlist:eq(#line)&&a",
      "name": "Text",
      "url": "href"
    }
  }
}
```

| 字段 | 说明 |
|---|---|
| `url` | 详情页模板，含 `{vid}`；若 `idIsUrl` 可为空（直接用 id） |
| `lines.list` | 线路节点列表 |
| `lines.name` | 线路名 |
| `lines.episodes.list` | 选集；`:eq(#line)` 用**线路下标**展开（0 起） |
| `lines.episodes.name/url` | 集名 / 集链接 |
| `lines.flat` | true 时无线路，全部集数进默认线路 `"主线"` |

**CMS / JSON 模式** 可用 `lines.fromField` / `lines.urlField` 指向 `vod_play_from` / `vod_play_url`（内部按 `$$$` `#` `$` 解析）。

### 5.4 search（搜索）

```json
"search": {
  "url": "/search/{wd}-{catePg}.html",
  "list": "body&&.module-item",
  "title": ".title&&Text",
  "id": "a&&href",
  "cover": "img&&data-src",
  "badge": ".note&&Text",
  "searchable": true,
  "quickSearch": true
}
```

字段同 category。`searchable/quickSearch` 也可写在 `caps`。

### 5.5 play（播放）

```json
"play": {
  "url": "{playUrl}",
  "headers": { "Referer": "{host}" },
  "parse": "auto"
}
```

| 字段 | 说明 |
|---|---|
| `url` | 最终地址模板；`auto` = 直接用详情里的集 URL |
| `headers` | 播放请求头（模板可含 `{host}`） |
| `parse` | `"auto"`（按扩展名判断）\| `"0"`（强制直链）\| `"1"`（标记 needsParse，不嗅探） |
| `filterAds` | string[]，命中广告域名则丢弃（合并全局 ads） |

**合规基线不变**：`parse:1` / 网页地址 → `needsParse=true`，默认过滤并提示，**不做网页嗅探**。

## 6. sourceType 各模式差异

### 6.1 html（默认）

选择器即 §4.1 CSS 链。适合：静态站、模板站、列表页爬取。

### 6.2 json

选择器用 `json:` 前缀。适合：前后端分离站、App 接口。

```json
"sourceType": "json",
"category": {
  "url": "/api/list?tid={cateId}&page={catePg}",
  "list": "json:data.list",
  "title": "json:name",
  "id": "json:id",
  "cover": "json:pic"
}
```

### 6.3 xml

选择器用 `xml:` 前缀。适合：老式 RSS/苹果CMS XML。

### 6.4 cms

**苹果 CMS JSON 快捷模式**——等价于现有 `CmsJsonSource`，但也可用 StarRule 携带自定义 UA/头：

```json
"sourceType": "cms",
"site": { "host": "https://api.example.com/api.php/provide/vod" }
```

此时 category/detail/search/play 由引擎按 CMS 协议填充，规则块可省略；若写了则覆盖默认选择器。

## 8. script（可选，非必须）

> **规范鼓励纯声明。** 仅当选择器实在表达不了时才用。

```json
"script": {
  "lazy": "function play(flag, id) { return input + id; }"
}
```

| 键 | 时机 |
|---|---|
| `preprocess` | 请求返回后、解析前（改写 body） |
| `lazy` | 播放地址二次加工 |

脚本在 QuickJS 沙箱执行，仅可调用注入的 `req/pdfa/pdfh/pd/input`；**不注入**文件系统、定时器、原生桥。超限熔断。

**三端保证**：无 `script` 的规则 → 手机/桌面/TV **行为完全一致**；有 `script` 的规则 → 三端均需 QuickJS（当前三端均已接 FlutterJs）。

## 10. 校验规则（导入时强制）

| 级别 | 规则 | 失败表现 |
|---|---|---|
| 致命 | `starrule` 缺失或 ≠1 | 不识别为 StarRule |

| 致命 | `site.host` 非 http(s) | 拒绝导入 |

| 致命 | `detail` 缺失 | 拒绝 |

## 12. 写源流程（给作者）

1. **抓站**：浏览器打开列表页 / 详情页，F12 看结构或接口。
2. **定 sourceType**：有 JSON 接口用 `json`；纯页面用 `html`；苹果CMS 用 `cms`。
3. **抠选择器**：列表 `list` 优先选「一个卡片一个节点」；字段用条目内相对链。
4. **填模板**：`{cateId}` `{catePg}` `{vid}` `{wd}` 对齐真实 URL。
5. **本地校验**：
   ```bash
   # 语法 + Schema（工具见 tools/starrule_lint）
   dart run tools/starrule_lint my.star.json
   ```
6. **三端试跑**：源管理 → 添加 → 粘贴/选文件 → 导入报告 → 测活 → 首页浏览。
7. **发布**：规则包或单文件；`meta.version` 变更即升级。

### 12.1 写源检查单

- [ ] `meta.id` 全局唯一且稳定（改 id = 新源）
- [ ] `site.host` 正确，无尾斜杠
- [ ] 列表 `list` 能命中 ≥1 条（测活通过）
- [ ] 详情能取出至少一条线路、一集
- [ ] 搜索（若声明）输入「爱」有结果
- [ ] 播放地址是直链（mp4/m3u8）或正确标记 `parse`
- [ ] 不需要的字段删掉，不写空规则
- [ ] 无 `script` 优先；有则注明原因

## 附录 A · 字段语义精确定义（与实现对齐 v0.1.0-dev.45）

### A.1 选择器求值顺序

1. 按 `&&` 拆成段序列。
2. 最后一段若为取值后缀（`Text` / `text` / `html` / 属性名）则取出，其余段为下钻选择器。
3. 仅有一段且是取值后缀时，对**当前节点自身**取值（用于条目内相对字段）。
4. `:eq(n)`：先取全集再取下标；`:eq(-1)` 取最后一个；`:eq(#line)` 由执行器替换为线路下标（0 起）。
5. 选择器子集基于 CSS（`tag` / `.cls` / `#id` / `tag.cls` / `div.item a`），非完整 XPath。

### A.2 占位符展开规则

| 占位符 | 编码 | 说明 |
|---|---|---|
| `{host}` | 不编码 | `site.host` 原样 |
| `{cateId}` | `encodeComponent` | 分类 id |
| `{cateName}` | `encodeComponent` | 分类名 |
| `{catePg}` | 不编码（整数） | 页码从 1 起 |
| `{vid}` | `encodeComponent` | 作品 id；若模板形如 `{vid}.html` 则先剥离 id 的扩展名，避免叠拼 |
| `{wd}` | `encodeComponent` | 搜索词 |
| `{playUrl}` | 不编码 | 详情取出的原始播放链 |
| `{lineId}` | 不编码 | 当前线路 id |
| `{filter_<key>}` | `encodeComponent` | 来自 `home.filters[].options[].value` |

### A.3 detail 的 workId 与 URL

| workId 形态 | 行为 |
|---|---|
| 以 `/` 或 `http(s)://` 开头 | **直接请求**该路径/URL（列表 href 常见形态） |
| 其它（如 `123`） | 套 `detail.url` 的 `{vid}` 模板 |
| `detail.url` 为空 | 直接请求 workId |

### A.4 字段后处理（对象形态）

```json
"title": {
  "sel": ".title&&Text",
  "regex": "^(.+?)\\s*更新",
  "replace": "$1",
  "default": "未知",
  "trim": true
}
```

| 步骤 | 规则 |
|---|---|
| 1 trim | 默认 true |
| 2 regex | 取第一个匹配；无捕获组用整段，有组用 group1；未命中 → `default` |
| 3 replace | **含 `$n`** 时作为正则替换模板（`$1`→group1…）；不含 `$` 时在结果上做字面量删除 |
| 4 default | 结果为空串时兜底 |
| 5 absUrl | true 时对 URL 结果补全绝对地址 |

字符串形态 `"title": ".title&&Text"` ≡ `{"sel": ".title&&Text"}`。

### A.5 分页 hasMore

| 模式 | 行为 |
|---|---|
| `auto`（默认） | 模板含 `{catePg}`：list 非空即有下一页；取到 `pageCount` 则以总页数为准。模板**不含** `{catePg}`：强制单页（防死循环） |
| `pageCount` | 必须能取到总页数；取不到视为无更多 |
| `none` | 永远单页 |

### A.6 CMS 线路分隔（`fromField` / `urlField`）

| 符号 | 含义 |
|---|---|
| `$$$` | 分线路（`vod_play_from` / `vod_play_url` 同步切分） |
| `#` | 线路内分集 |
| `$` | `集名$地址` |
| `###` | 兼容误写，等同 `$$$` |

### A.7 needsParse 判定

| play.parse | 行为 |
|---|---|
| `0` | 强制直链 |
| `1` | 强制 `needsParse=true`（星映默认过滤并提示，**不嗅探**） |
| `auto`（默认） | 含 `.m3u8/.mp4/.flv/.mkv/.ts` 或 `rtmp/rtsp` → 直链；其余 http → needsParse |

## 附录 E · FAQ

**Q1：为什么不直接用 drpy rule？**  
A：drpy 含 `js:` 时绑死 QuickJS；StarRule 默认纯声明，三端零脚本即可跑，且可 JSON Schema 校验。

**Q2：列表 id 是 `/detail/1.html` 还是 `1`？**  
A：都可以。以 `/` 或 `http` 开头直接当 URL；否则进 `{vid}` 模板。写源时二者择一，保持一致。

**Q3：为什么搜索框置灰？**  
A：未声明 `search` 块，或 `caps.searchable=false`，或导入校验将 search 块判为缺 `list/title/id`。

**Q4：桌面不能播某源？**  
A：若徽章是「jar 蜘蛛」，桌面无 JVM 桥；请用 StarRule 重写该站行为。StarRule 无 script 的规则三端都能跑。

**Q5：如何版本升级规则？**  
A：改 `meta.version`（semver）。订阅刷新会按 `meta.id` 对齐；**改 id = 新源**。

**Q6：`script` 能干什么？**  
A：仅 `preprocess`（改写 body）与 `lazy`（播放地址二次加工），QuickJS 沙箱，不注入文件系统/定时器/原生桥。
