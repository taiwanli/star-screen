## 1. 环境搭建

| 依赖 | 版本要求 | 说明 |
|---|---|---|
| Flutter SDK | ≥ 3.47 stable（本机 3.47.5 / Dart 3.13.4） | 路径建议纯 ASCII |
| Git | ≥ 2.40 | |
| Windows 构建 | VS 2022「使用 C++ 的桌面开发」负载 | `flutter doctor` 检查 |
| Android 构建 | Android SDK 34+ / JDK 17 | 手机与 TV 共用工具链 |
| 网络 | pub.dev 不可达时走本地代理 | 本机 iKuuuVPN：`127.0.0.1:7890` |

```bash
# 检查环境
flutter doctor

# 依赖解析（workspace 根一次完成，勿在各包单独 get）
# 网络受限时先设代理：
#   set HTTP_PROXY=http://127.0.0.1:7890 && set HTTPS_PROXY=http://127.0.0.1:7890
flutter pub get
```

**已知的本机注意事项**：
1. 工作目录含中文（星映）时 `flutter analyze` 的 LSP 通道会崩溃（Content-Length 编码问题）——**一律用 `dart analyze`**（CI 的 GitHub 路径为 ASCII，无此问题）。
2. 同理，`build_runner` 的 AOT 构建脚本无法写入中文路径——先执行 `subst S: "C:\Users\Administrator\Desktop\星映"`，再在 `S:\` 下运行代码生成。
3. `flutter test` 多包连跑会出现编译缓存假失败——**按端分别执行**（CI 已按此拆分）。
4. drift 运行时测试需要 sqlite3 原生库：CI（ubuntu）装 `libsqlite3-dev` 即可；本机 Windows 若未装 sqlite3.dll，storage 测试会自动跳过（测试内含可用性探测）。

## 2. 工程结构（现状）

```text
星映/
├─ apps/
│  ├─ desktop/        # Windows 壳（flutter create windows 平台已生成）
│  ├─ mobile/         # Android 手机壳（android 平台已生成）
│  └─ tv/             # Android TV 壳（android 平台已生成；Leanback 属性见里程碑 M3）
├─ packages/
│  ├─ domain/         # ★ 领域层：统一源契约 / 模型 / M0 配置解析管线（纯 Dart，27 测试）
│  ├─ ui_kit/         # 设计系统：StarTheme/StarTokens/StarPoster + tokens/（json+css）
│  ├─ player/         # PlayerController 契约 + 回退链（4 测试；平台实现 M1 接入）
│  ├─ plugins/        # JS 沙箱限额 / drpy 契约接口 / 导入器接口（实现 M3）
│  └─ storage/        # KeyValueStore/BackupCodec 抽象 + db/schema.sql（drift 接入 M0 收尾）
├─ docs/              # 01–09 设计与开发文档
├─ design/ui/         # 三端高保真视觉稿（HTML 画板 20 屏）
├─ tools/             # check_architecture.dart 架构守护
└─ .github/workflows/ # CI：analyze / arch-guard / test
```

**依赖方向（红线）**：`apps → ui_kit →（无）`；`apps → domain`（经将来的 providers 层）；`domain/player/plugins/storage` 互相之间仅允许 player/plugins/storage → domain；**domain 永不依赖 flutter/UI**（CI 的 `arch-guard` 任务强制）。

## 3. 日常命令速查

```bash
# 静态分析（本地一律用 dart analyze，原因见上）
dart analyze

# 单元测试（纯 Dart 包，在各包目录内）
dart test packages/domain        # 或 cd packages/domain && dart test
dart test packages/player

# 组件测试（按端执行）
flutter test apps/desktop
flutter test apps/mobile
flutter test apps/tv

# 架构守护
dart run tools/check_architecture.dart

# 三端运行
flutter run -t lib/main.dart -d windows        # 在 apps/desktop 内
flutter run -t lib/main.dart -d <device-id>    # 在 apps/mobile / apps/tv 内
```

## 4. 代码与令牌规则

1. **组件禁止硬编码视觉值**：颜色/尺寸一律取 `StarTheme.of(context)`（Dart）或 `--sys-*`（Web/文档）；令牌唯一来源 = `packages/ui_kit/tokens/design-tokens.json` + `tokens.*.css` + `star_ui_kit.dart`，三者改动必须同步并在 CHANGELOG 记录（规范 §8.5）。
2. **禁用 `flutter analyze` 于本地中文路径**（见 §1）；提交前本地必须通过：`dart analyze` + 相关联测试 + 架构守护。
3. **领域层禁 UI 依赖**；新增跨包依赖需在评审中给出依据。
4. **注释与文案**：用户可见文案必须查 07 文档 §4.2 术语表（新增词先补表）；注释解释"为什么"，不复述"是什么"。
5. **测试资产**：新格式/新容错场景 → 先在 `packages/domain/test/fixtures/` 加脱敏样本再写测试（参照 06 清单来源）。

## 5. 版本与协作

- **分支**：`main`（受 CI 保护）+ 短命特性分支 `feat/<里程碑>-<主题>`，如 `feat/m1-cms-json-adapter`。
- **提交**：Conventional Commits（`feat:/fix:/test:/docs:/chore:`），一个提交一件事。
- **变更日志**：每次合入 main 前更新 `CHANGELOG.md`（Keep a Changelog 格式）。
- **里程碑对应 docs/09 的任务编号**；完成一条勾一条，CHANGELOG 与任务表同更新。
- **许可证**：Apache-2.0（见 LICENSE 补充说明）；引入新依赖时先过许可证清单（IJK/ GPL-compiled libmpv 有额外义务，docs/03 §1.4）。
- **合规红线（不可协商）**：不内置任何内容源；不实现嗅探/第三方解析（`parses`/`rules` 不导入）；jar 永不下载执行；测试样例仅存文档与 fixtures，不进应用推荐位。

## 7. 代码生成一致性（drift / build_runner）

1. `packages/storage` 的表结构由 `drift` 定义（`lib/src/db/star_database.dart`），生成的 `star_database.g.dart` 已提交进仓库——**schema 变更必须同步重新生成并连同 `.g.dart` 一起提交**，否则 CI 会因类型不匹配而失败。
2. 重新生成：`dart run build_runner build --delete-conflicting-outputs`（中文路径需先 `subst S:`，见 §1 注意事项 2）。
3. 生成一致性校验（docs/13 C4）：CI 可增加「运行 build_runner 后 `git diff --exit-code`」步骤，确保提交内容与可再生结果一致，防止手工改 `.g.dart`。
