## 2. 产品概览

五款产品中四款属于同一"**TVBox 生态**"，本质都是"**播放器空壳 + 外部配置驱动多源**"模式：软件本身不含影视资源，内容完全由用户配置的第三方接口决定。差异主要在**上手门槛**（空壳 vs 内置源）与**源管理能力**（单仓 vs 多仓）。

| 维度 | TVBox | 影视仓 | 影迷 | 喵影视 | 可视TV |
|---|---|---|---|---|---|
| 生态归属 | 生态源头 | TVBox 知名二改 | 独立小工作室 | 猫影视→TVBox 衍生壳 | 俊版 TVBox + 影视仓二改 |
| 开源性 | 开源（Apache 系） | 闭源 | 闭源 | 闭源 | 闭源 |
| 平台 | 安卓 TV + 手机 | 安卓 TV + 手机 | 安卓手机 + TV | 安卓手机 + TV | 安卓 TV 为主 + 手机版 |
| 桌面版 | 无（社区模拟器/移植） | 无 | 无 | 无 | 无 |
| 源机制 | 配置接口 JSON（spider jar/JS） | 单仓 + **多仓聚合** + 本地包 | 内置库宣传 + JSON 订阅源并存 | 内置源版 + 配置地址版双模式 | 仓库/多仓配置，Max 版内置部分源 |
| 直播 IPTV | ✅ m3u/txt/json + EPG | ✅ | 无证据 | ✅（TV 版） | ✅ |
| 上手门槛 | 高 | 中（新手相对友好） | 低-中 | 低(内置)/高(自定义) | 中 |
| 维护状态 | 原仓库已删，fork 活跃 | 活跃但渠道封闭 | 版本线混乱，看似活跃 | 停服-复活式，碎片化 | 较活跃 |
| 明显短板 | 配置门槛、源失效 | 闭源、假冒版本泛滥 | 口碑存疑 | 口碑差（5.8/10） | 源失效、配置门槛 |

## 3. 逐产品详解

### 3.1 TVBox —— 生态源头，功能标杆

**定位**：开源安卓端影视聚合播放器，"只做播放器，不抓源"。无官方桌面版。

**核心功能**：
- **多源聚合**：一个"配置接口"（远程 URL / 本地 JSON）加载几十上百个点播站点；支持**聚合搜索**（一次搜多站）与**多线路换源**（同一影片列出各站资源）。
- **爬虫插件**：spider jar（Java 爬虫）或 JS 爬虫（QuickJS），支持全局 `spider` 与站点级 `jar`。
- **直播**：m3u/txt/json 直播订阅，支持 EPG、多线路。
- **解析接口**：网页嗅探、JSON 解析、并发/轮询解析策略（用于提取网页视频直链）。
- **播放**：内核可切换 **系统 / IJK / ExoPlayer**，软硬解切换、倍速、跳过片头片尾、本地字幕。
- **收藏 / 历史 / 断点续播**：均支持，数据存本地。
- **配置下发**：内置局域网 HTTP 服务（默认 9978 端口，浏览器访问 `http://电视IP:9978` 粘贴配置）、扫码配置（同一 WiFi）、本地文件导入。
- **其他**：去广告开关、缓存清理、DOH 加密 DNS、壁纸。

**界面布局（TV 端）**：
- 首页：顶部 Tab（点播/直播/搜索/设置）+ 推荐区（可配置：豆瓣推荐/站点推荐/观看历史）+ 海报墙横向焦点滚动。
- 分类页：左侧/顶部分类筛选 + 右侧海报网格。
- 详情页：影片信息 + 剧集列表 + 线路/换源入口。
- 播放页：全屏，菜单键呼出设置菜单（倍速、线路、解码、字幕、跳片头片尾、刷新）。
- 设置页：配置地址（粘贴/扫码/本地）、播放器选择、聚合搜索开关、去广告等。
- 手机版界面相对简陋（无 Leanback 焦点优化的网格列表），社区因此更推荐 FongMi 版的双 UI。

**交互方式**：五向键移焦、OK 确认、菜单键呼出设置/播放菜单、返回键逐级退出；播放中左右快进快退；触屏支持滑动快进、亮度/音量手势（社区通例）。

**源接口机制（配置 JSON 关键字段）**——这是全生态的"事实标准"，自研产品需要兼容：
- `spider`：全局爬虫 jar 地址（如 `./spider.jar;md5;xxx`），站点级 `jar` 优先。
- `sites`：`key`/`name`/`type`/`api`/`searchable`/`filterable`/`ext`/`jar`/`playerType`。`type=3` 为爬虫源（`csp_XXX` 类名或 JS）；`type=0/1` 为 MacCMS 标准 CMS 内置源（0/1 与 XML/JSON 的对应关系社区记载不一致，以实现为准）。
- `parses`：`name`/`url`/`ext`，type 0=嗅探、1=网页解析、2=JSON 解析。
- `lives`：`name`/`type`/`url`（m3u/txt/json）/`epg`/`logo`。
- 其他：`wallpaper`、`rules`（广告过滤）、`doh`。
- **多仓**："仓库的仓库"，聚合多个单仓地址的 JSON/TXT，应用内像货架一样切换。

**优点**：免费开源、无官方广告；自由度极高；功能最全；开源透明可自行编译。
**缺点**：上手门槛高（新手必须看教程）；**源失效快**（社区称约 40% 免费源一个月内失效）；第三方源有广告注入与隐私风险；版本混乱；版权合规风险高。

### 3.2 影视仓 —— TVBox 的"新手友好版"

**定位**：TVBox 二次开发的闭源修改版（社区流传作者为"安卓哥"，未核实到官方页面）。主打 Android TV，兼有手机版。

**核心功能**：与 TVBox 同源（完全兼容其配置 JSON，spider/直播/解析体系通用），最大差异点：
- **多仓聚合导入**：一次填入多仓地址，界面内直接切换多个单仓/线路，不用反复改配置。
- **单仓/多仓/本地包**：本地包 = 打包接口+直播源+EPG+皮肤的离线包。
- 界面更简洁、美化程度更高、导航层级更浅（社区："新手建议影视仓，喜欢功能丰富的用 TVBox"）。
- v6 时代修复直播卡顿与 EPG 延迟，新增自定义源导入模板。

**界面布局**：沿用 TVBox 骨架（首页推荐/海报墙 + 点播/直播/搜索/设置入口 + 分类页 + 详情选集 + 播放页 + 设置页），视觉更精致。

**优点**：上手简单；多仓管理高效；界面美观；与 TVBox 接口互通可互为备用。
**缺点**：源失效仍是最大痛点；H.265/4K 高码率音画不同步反馈较多；**闭源**且分发渠道杂，假冒捆绑版本泛滥；版权合规风险。

### 3.3 影迷 —— 偏商业化的聚合 App

**定位**：免费影视聚合播放平台（闭源，"影迷工作室"，无官网），安卓手机/平板/TV，无 iOS 与桌面版。

**核心功能**：
- 多源：介绍页称"内置资源库每日更新"；同时另有版本线提供**添加 JSON 订阅源**（TVBox 风格）的教程——两版本线架构可能不同（推断）。
- 搜索：关键词/演员/拼音首字母，模糊搜索。
- 分类筛选：类型/地区/年份/评分多维筛选 + 榜单（热播/好评/新片/票房/短剧）。
- 播放：单片 6–10 条线路；标清–4K 四档清晰度；0.5–4 倍速；字幕自定义（大小/颜色/位置）、外挂字幕、双语字幕；画面比例；P2P 加速。
- 收藏/历史：自动记忆进度续播；有"播放历史云同步"（版本说明）。
- 缓存下载：批量/后台/断点续传（仅 App 内播放，不可导出）。
- 投屏：DLNA、Chromecast、AirPlay。
- 直播：无证据。少儿模式：无证据。

**界面布局**：公开截图极少。从功能描述可归纳：首页榜单 + 个性化推荐；分类页多条件筛选；搜索联想。"我的"/设置页结构无公开资料（推断 TV 端为遥控器优化的海报墙布局）。

**优点（宣传侧，可信度存疑）**：资源全、更新快、4K 流畅、字幕倍速对老人友好、无广告。
**缺点**：好评疑似下载站软文，无独立评价佐证；无官方主体；版本混乱（v2.4.0 与 v4.9.x 两线并行）；分发渠道存在污染与二次打包风险；版权风险明确。

### 3.4 喵影视 —— 猫影视衣钵，"停服-复活"生态

**定位**：安卓聚合播放器（包名 com.meowtv.lives），猫影视（CatVodTV）停运 → 开源出 TVBox → 衍生壳生态的一员，与影视仓同配置体系。手机 + TV 双版本。

**核心功能**：
- **双模式**：TV 版分"内置源版"（内置 15 大影视源，打开即用）与"自定义版"（设置→配置地址→粘贴接口 URL）。
- 聚合搜索（宣称汇聚全网百站）；分类齐全；号称 80+ 线路可切换；多画质切换。
- 历史/收藏；离线缓存；TV 版内置直播频道。
- 投屏、字幕、少儿模式：无公开资料（推断无或极弱）。

**界面布局**：截图级资料缺失。可确认动线：主页（热门推荐 + 按历史的智能推荐）→ 分类 → 详情选集/换线路 → 播放页；**设置页的"配置地址"是源管理核心入口**。TV 版以"直播 + 点播"并列主打，安装包刻意轻量（约 22.6MB）。

**优点**：内置源版零配置上手快；免费；功能覆盖点播+直播。
**缺点**：口碑差（某下载站 500+ 人评分仅 5.8/10，有"无法打开"差评）；版本碎片化严重（高级版/重生版/复活版/魔改版并存），反映上游停服、接口失效的动荡；无售后；安装包多手分发有篡改风险。

### 3.5 可视TV —— 俊版 TVBox + 影视仓的二次整合

**定位**：安卓大屏免费影视聚合（"云星日记"基于俊版 TVBox + 影视仓二次修改，未核实官方页面）。TV/投影为主，兼手机版与"共存版"。

**核心功能**：
- 仓库/多仓配置加载源（设置→配置地址→输入仓库地址）；Max 版内置部分源降低门槛。
- 聚合搜索（可开关）；分类细分（宣传各 19 类）；首页推荐板块可选（豆瓣/站点/历史）。
- 详情选集、多线路/多源切换、倍速、跳片头片尾、1080P/4K 宣传。
- 收藏/历史/断点续播（影视仓系标配，界面细节为推断）。
- 直播：央视/卫视频道，直播源经"菜单键→设置→订阅配置"填入；支持启动默认进直播或点播。
- **网盘挂载**：Alist / WebDAV / 本地目录，可播网盘 4K 资源——同类中较有特色的扩展。
- 播放器内核：默认 ijk，可选 EXO，渲染方式可选（SU），软硬解切换（TVBox 系通例）。

**界面布局**：顶部横向 Tab（点播/直播/搜索/设置）+ 内容卡片网格（俊版改版样式），焦点在顶栏与内容区间上下移动；详情页"海报+信息+选集网格"；播放页全屏 + OK/菜单键呼出控制层（部分推断）。

**交互**：五向键 + OK + 菜单键（播放页呼出跳片头/倍速/刷新/线路；直播页呼出订阅配置）；扫码配置；直播 OK 呼出频道列表，数字键换台（推断，TVBox 系直播惯例）。

**优点**：免费免登录；多仓切换灵活；双端可用；网盘挂载与 4K 是亮点；更新较频繁；界面较原版美化。
**缺点**：源失效快、冷门内容易失效；配置错误是"大部分人用不了"的首要原因；广告无法全屏蔽；部分设备硬解黑屏/有画面无声（需切软硬解或换 EXO 兜底）；版本渠道杂乱。

## 4. 共性特点总结

### 4.1 功能共性矩阵

| 功能 | TVBox | 影视仓 | 影迷 | 喵影视 | 可视TV | 结论 |
|---|---|---|---|---|---|---|
| 多源聚合（配置驱动） | ✅ | ✅ | 部分✅ | ✅ | ✅ | **全行业标配，是产品灵魂** |
| 聚合搜索 | ✅ | ✅ | ✅ | ✅ | ✅ | 标配 |
| 分类浏览 + 筛选 | ✅ | ✅ | ✅（多维） | ✅ | ✅ | 标配 |
| 详情选集 | ✅ | ✅ | ✅ | ✅ | ✅ | 标配 |
| 多线路/换源 | ✅ | ✅ | ✅ | ✅ | ✅ | 标配（源失效的救命稻草） |
| 清晰度切换 | ✅ | ✅ | ✅(4档) | ✅ | ✅ | 标配（依赖源提供） |
| 倍速 | ✅ | ✅ | ✅(0.5-4x) | ✅ | ✅ | 标配 |
| 字幕 | 本地字幕 | 本地字幕 | 最强（样式/外挂/双语） | 无资料 | 无资料 | 参差不齐，机会点 |
| 收藏/历史/续播 | ✅ | ✅ | ✅(+云同步) | ✅ | ✅ | 标配，但普遍**仅本地** |
| 直播 IPTV | ✅ | ✅ | ✖ | ✅ | ✅ | TV 端普遍带 |
| 投屏/推送配置 | ✅(9978网页+扫码) | ✅ | ✅(DLNA等) | 无资料 | 扫码 | 配置推送普遍，视频投屏参差 |
| 缓存下载 | 部分 | 部分 | ✅(强) | ✅ | ✅(Max) | 参差 |
| 网盘挂载 | 部分 fork | ✖ | ✖ | ✖ | ✅(Alist/WebDAV) | 差异化能力 |
| 播放器内核切换 | ✅(系统/IJK/EXO) | ✅ | 无证据 | 推断✅ | ✅(ijk/EXO) | 标配，兼容性兜底 |

### 4.2 六大共性设计模式

1. **空壳 + 配置驱动的多源聚合**：软件不内置内容，靠配置接口/仓库注入站点列表、爬虫、直播源。好处是内容中立、生态开放；代价是上手门槛与源稳定性问题。
2. **海报墙为中心的四级浏览动线**：首页推荐 → 分类列表 → 详情（信息+选集+线路）→ 全屏播放。这是全生态最稳定的 IA（信息架构）。
3. **聚合搜索 + 多线路换源**：搜索一次返回多站结果、按源分组渐进加载；详情页/播放页随时换线路换源——这是对抗"源失效"的核心手段。
4. **本地收藏/历史/断点续播**：数据全在本地 SQLite，无账号体系，导致多设备不同步（影迷宣称云同步是少数例外）。
5. **点播 + 直播一体**（TV 端）：直播用 m3u/txt 订阅，数字键换台、频道列表是惯例。
6. **配置下发通道多样**：URL 粘贴 / 扫码（需同 WiFi）/ 本地文件 / 局域网网页控制台（9978）。手机当"遥控配置器"是成熟模式。

### 4.3 界面布局共性

- **TV 端**：顶部横向 Tab 或左侧竖栏 + 海报卡片网格；焦点卡片放大 + 描边/光晕；详情页"左侧海报信息、右侧选集网格"；播放页全屏，OK/菜单键呼出控制层与菜单（倍速/线路/解码/跳片头片尾/刷新）。
- **手机端**：底部 Tab 导航 + 顶部分类横滑 chip + 两三列海报网格；播放页手势操作。
- **设置页**：均为纵向列表，播放器内核、软硬解、配置地址、缓存管理是共有项。

### 4.4 交互共性

- **遥控器**：五向键移焦、OK 确认/呼出控制条、菜单键呼出当前页操作集、返回键逐级回退、数字键（直播换台/搜索输入）。
- **手机播放页手势**：左侧上下滑调亮度、右侧音量、水平滑进度、单击显隐控制栏、双击暂停、长按倍速。
- **播放内核策略**：ijk/EXO/系统 三选一 + 软硬解切换，作为"万能兜底"。

## 5. 缺点与痛点（自研必须规避的问题清单）

1. **源失效快、可用性差**：约 40% 免费源一月内失效；冷门内容换源失败率高；直播源频繁失效。→ 用户最大抱怨。
2. **配置门槛高**：填仓库地址、扫码（需同 WiFi）失败率高，"配置错误是大部分人用不了的首要原因"。
3. **播放兼容性差**：4K/高码率卡顿、音画不同步、部分盒子硬解黑屏、有画面无声——需要用户手动切内核/软硬解，体验粗糙。
4. **数据孤岛**：收藏/历史仅存本地，换设备即丢失；无账号、无同步（或同步极弱）。
5. **安全与信任问题**：闭源二改 + 多手分发 → 山寨、捆绑、篡改；第三方源广告注入与隐私风险。
6. **体验细节粗糙**：TV 焦点丢失/跳变、不同源字段不统一导致界面错乱、聚合搜索结果质量参差、无统一设计语言（TVBox 手机版尤其明显）。
7. **合规风险**：聚合未授权内容，下架与法律风险高（这也是 TVBox 原仓库被删的原因）。

## 6. 对"星映"的启示（设计原则）

| # | 原则 | 来源痛点/经验 |
|---|---|---|
| P1 | **内容中立**：产品只做聚合播放框架，**不内置任何内容源**，首次启动引导用户添加自有合法源 | 全生态合规教训（TVBox 被删仓） |
| P2 | **源可用性是一等公民**：源健康度检测、自动优选、多源容灾、播放失败一键换线路/换源 | 痛点 1 |
| P3 | **零门槛上手**：内置"标准 CMS JSON API 直连"源类型（无插件即可用）；URL 粘贴/扫码/局域网推送三种配置通道；配置导入向导 | 痛点 2，影视仓多仓经验 |
| P4 | **播放兜底自动化**：默认 EXO，失败自动回退软硬解/换内核，再失败提示换线路；内核切换保留手动入口 | 痛点 3 |
| P5 | **数据可迁移**：本地 SQLite + 导出/导入 + 局域网多端同步（收藏/历史/配置） | 痛点 4 |
| P6 | **开源透明 + 插件沙箱**：核心开源，自定义爬虫源以 JS 沙箱执行（限网络、限文件、限时长），不做原生 jar 动态加载 | 痛点 5 |
| P7 | **三端一体、分端输入**：一套设计语言，TV 焦点导航 / 手机手势 / 桌面键鼠三套输入适配；TVBox"手机版简陋"是反面教材 | 痛点 6，FongMi 双 UI 正面经验 |
| P8 | **统一元数据视图**：对源返回的字段做清洗归一（标题/海报/年份/备注），异构源也能渲染一致 | 痛点 6 |
| P9 | **兼容而非依赖 TVBox 生态**：提供 TVBox 配置导入器降低迁移成本，但内部模型自有标准 | 生态经验 |
| P10 | **点播优先、直播与网盘为扩展**：直播（m3u/数字键）P1 实现；Alist/WebDAV 挂载作差异化 P2 | 可视TV 差异化启发 |
